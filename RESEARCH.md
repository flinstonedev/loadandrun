# Computing-focused research expansion

Checked 4 September 2026. Scope: software, programming environments, HCI, knowledge tools and computer systems. Excludes furniture, buildings and urban-planning proposals.

The criterion is documented originality plus a specific computing proposal. Historical prototypes are not automatically unfinished opportunities: modern descendants and the remaining gap need to be identified before promoting a candidate as a revival opportunity. Adoption histories for the six imported design examples have not been verified; the product no longer displays adoption verdicts.

## David Canfield Smith — Pygmalion (1975)

The thesis describes an implemented visual programming environment with icons and an editor that remembers operations. This is a concrete starting point for studying programming through examples. It was not merely an unbuilt proposal.

- [Original thesis](https://worrydream.com/refs/Smith_DC_1975_-_Pygmalion.pdf)
- [Henry Lieberman’s retrospective, A Creative Programming Environment, Remixed](https://web.media.mit.edu/~lieber/Publications/Pygmalion-Remixed.pdf)

Suggested investigation (editorial): reconstruct one worked example and compare it to contemporary programming-by-demonstration systems. Adoption history, availability of an executable version, and the specific surviving gap are not yet established.

## Ira Goldstein and Daniel Bobrow — PIE (1980–1981)

The original authors describe an experimental Smalltalk environment using perspectives, contracts, contexts and layers to represent programmes and alternative designs. Their contribution connects knowledge representation to interactive development.

- [Descriptions for a Programming Environment, author-uploaded paper](https://www.researchgate.net/publication/221604325_Descriptions_for_a_Programming_Environment)
- [Original PARC reports](https://worrydream.com/refs/Goldstein_1981_-_PIE_four_reports.pdf)

Suggested investigation (editorial): build a tiny example with two alternative designs sharing a base and retaining constraints. Compare it with version control and current IDEs. The sources establish the prototype, not a claim that it was abandoned or that its ideas have no modern implementation.

## David Harel and Rami Marelly — play-in/play-out (2003)

Their Play-Engine lets a user demonstrate scenarios through a GUI and execute behaviour using live sequence charts. The book included software. Later publications continued this direction, so “never built” or “abandoned” would be misleading.

- [Authors’ book page and software description](https://www.weizmann.ac.il/math/harel/come-lets-play)
- [Subsequent work integrating scenarios and Statecharts](https://arxiv.org/abs/1911.10691)

Suggested investigation (editorial): reproduce a small scenario and compare the inspectability of requirements with conventional code and tests. This is a comparison candidate pending a current adoption and gap review.

## Editorial corrections and next research

The original 100-entry Markdown is preserved as source material, not treated as verified publication copy. Its categorical claims such as “never shipped”, “never adopted” and “no working tool” need checking individually. Current implementations could invalidate them.

The research archive retains 62 computing-related seed entries and five additions. The local People directory contains only people linked to the two historical entries retained by the original source-rights review; the current catalog also includes the later expansion to 41 briefs described below. Domain-adjacent items remain only where the proposal is a computing system (for example computer-based learning and decision support). Physical design, furniture and city-planning entries are excluded.

Next: choose a small number of strongest candidates, locate original software or papers, compare current successors, and record a falsifiable missing capability for each. Do not infer merit, feasibility or non-adoption from a person’s reputation.
